# Design and trade-offs

The vertical slice uses Python iterators rather than a dataframe so input size does not determine source-row memory use. Temporary SQLite primary-key tables handle deduplication and output reconciliation on disk, avoiding unbounded in-memory key sets. The customer reference set remains in memory for simplicity, so very large dimensions should move to a database lookup. Publishing uses a sibling staging directory and same-filesystem renames after reconciliation; a backup directory supports rollback on rename errors and recovery after interruption. Deterministic hashing of both input names and contents makes retries idempotent. Rejects preserve source row and raw values where parsing succeeded. CSV and newline-delimited JSON are supported because both permit record-at-a-time reads; a single large JSON array is intentionally not supported.

Output is one normalized CSV plus line-delimited reject JSON and a JSON operational report. This is easy to inspect locally and can be replaced by object storage or a warehouse sink later. The pipeline rejects unsupported currency/status and timezone-free timestamps rather than silently guessing. It permits out-of-order business timestamps because the feed is a snapshot, and it does not overwrite records across different source files.
